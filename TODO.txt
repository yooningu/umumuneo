[백엔드] 미니 PC에서 아래 정리 필요 (이메일 첨부파일을 NAS files 테이블로 합침)
예전엔 이메일 첨부파일을 email_attachments 테이블 + 별도 디스크 경로(uploads/email-attachments/)에
따로 저장했는데, 이제 NAS가 쓰는 files 테이블(source=EMAIL)로 합쳐서 더 이상 안 씀.
files 테이블의 새 컬럼(source, email_id)은 nullable이라 Hibernate가 배포 시 자동으로 추가함 -
아래 두 가지만 직접 정리하면 됨.

1. DB에서 실행: DROP TABLE email_attachments;
2. 미니 PC 디스크에서 삭제: /workspace/uploads/email-attachments/ 폴더 통째로

[백엔드] 미니 PC에서 아래 정리 필요 (User.email 필드 삭제)
users 테이블의 email 컬럼은 어디서도 값을 넣어준 적 없는 죽은 필드라 코드에서 지웠음(entity/User.java,
UserResponse). Hibernate ddl-auto=update는 컬럼을 자동으로 "추가"만 하고 "삭제"는 안 해줘서,
DB에는 아직 email 컬럼이 그대로 남아있음 - 직접 지워야 함.

1. DB에서 실행: ALTER TABLE users DROP COLUMN email;

[백엔드] 미니 PC에서 아래 정리 필요 (메모장 여러 개 지원 - memos.user_id 유니크 제약 제거)
메모장을 유저당 1개에서 브라우저 탭처럼 여러 개로 바꾸면서 entity/Memo.java를 @OneToOne(unique=true)에서
@ManyToOne으로 고쳤음. Hibernate ddl-auto=update는 컬럼/제약을 "추가"만 하고 기존 유니크 인덱스는
안 지워줘서, DB에는 아직 user_id 유니크 제약이 그대로 남아있음 - 이 상태로 두면 메모를 2개째
만들 때 DB 에러가 남. 직접 지워야 함.

1. DB에서 실행: SHOW INDEX FROM memos; 로 user_id 쪽 유니크 인덱스 이름 확인
2. DB에서 실행: ALTER TABLE memos DROP INDEX <확인한 인덱스 이름>;
